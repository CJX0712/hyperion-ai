# ADR-011 联合多任务训练：修复 BE/CE 对 LM 的灾难性遗忘

状态：已采纳 · 作者：晨星

## 背景
原训练为四阶段串行共享同一套 Transformer 权重：

```
LM → 双塔(BE) → 交叉编码器(CE) → 导出
```

跨引擎交叉验证（`tools/xcheck_lm.py`）暴露了一个严重缺陷：最终导出权重的
LM loss 为 **3.1511（ppl 23.36）**，而 LM 阶段结束时只有 **0.0838（ppl 1.087）**。
-loader 经检索回放校验无误（Python 与 TS 权重语义一致），说明这是**训练侧**
而非推理侧问题。

现象：生成时输出退化为无限重复 `：` 或 `，`（贪心解码也在重复，且在训练原生
格式下同样退化）。跨引擎验证把「模型坏了」压缩成可机械定位的结论——LM 能力被
后续对比学习阶段覆盖。

### 根因
BE / CE 的对比学习目标（均值池化 + L2 归一 + InfoNCE / 组内 softmax）会把共享
主干改写成「所有 token 向量近似相等、方向趋同」的嵌入空间。这恰好与自回归 LM
所需的「token 之间丰富、可区分的方向动态」相冲突。BE/CE 在 LM 已训好的权重上
继续微调共享参数，等于用一股更强的梯度把 LM 动态整片擦除——即**灾难性遗忘**。
LM loss 从 0.08 一路涨到 3.15 正是这一过程的量化证据。

## 决策
在原有三阶段后新增**阶段 4：联合多任务训练**（`train_joint`，`src/py/hyperion/train.py`）：

```
每步随机选一个任务，三者共用一个 AdamW 优化器：
  - LM         概率 = joint_lm_ratio（默认 0.6）
  - 双塔 BE    概率 = (1 - lm_ratio) / 2
  - 交叉编码 CE 概率 = (1 - lm_ratio) / 2
```

- BE 的 `emb_proj` 与 CE 的 `ce_score` 在阶段 2/3 训练后直接交给联合阶段，
  不再随机初始化，避免丢失已学检索能力；
- 联合阶段以高比例 LM 回放，**持续刷新共享主干**，使同一套权重同时具备
  「会续写」与「会检索」两种能力；
- 学习率取 `lr*0.5`，与 BE/CE 阶段同量级，避免破坏已收敛区域；
- 导出权重改为取联合阶段末的 `emb_proj` / `ce_score`。

### 配套修正：LM 语料补 EOS
原 `lm.txt` 各段之间无 `<eos>`，模型从未学过「何时停止」。在 `main()` 中将
每段 `tok.encode(text, add_eos=True)` 后再拼接，教模型在完整表述后输出 `<eos>`；
TS 推理侧（`src/ts/infer/index.ts:129`、`:186`）已正确实现 `EOS_ID` 停止，无需改动。

## 后果与验证
- 生成退化（重复符号）应消失：LM loss 在联合阶段末回到 ~0.1 量级；
- 检索/重排能力不回退：`npm run verify` 的 e2e 与 selfcheck 仍全绿；
- `tools/xcheck_lm.py` 复算的最终权重 LM loss 作为回归守门指标，应远低于 1.0，
  否则视为联合阶段 LM 回放不足，需上调 `--joint-steps` 或 `--joint-lm-ratio`。

## 备选方案（已被否决）
- **冻结主干、只训头**：检索头独立无法弥补 LM 退化，且 BE/CE 头依赖主干表征；
- **重排训练顺序（先 BE/CE 后 LM）**：LM 在最后单阶段难同时支撑检索表征；
- **单独存两套权重**：违背本项目「单权重多能力」的设计约束，推理侧需分支，
  增加部署复杂度。联合训练在单权重下同时保住两种能力，是最简解。
