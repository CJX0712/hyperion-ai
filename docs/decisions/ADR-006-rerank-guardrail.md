# ADR-006 重排护栏：分数级归一化融合，融合通道主导

状态：已采纳（v2，替代初版的 RRF 再融合方案） · 作者：晨星

## 背景
交叉编码器重排器是 1.3M 参数模型，不保证比混合融合（BM25+稠密 RRF）更准。
直接把重排分数当最终排序时，重排器的任何退化都直接伤害用户。

初版护栏采用「重排结果 + 原始融合 → 再做一次 RRF 排名融合」（`rrfFuse` 权重 1:1）。
但在 e2e 回归里暴露了一个真实缺陷：一条在混合检索里排第一的**强词法命中**
（用户刚入库的文档、用精确关键词查询），会被交叉编码器在二次 RRF 中反超——
只要交叉编码器把某个候选抬到 `scored-rank-1`，它就能同时吃满两路加成，
反超融合通道的 rank-1 强命中，导致该文档跌出 top-k，用户「用刚入库的关键词却查不到」。

根因：RRF 只看**排名**不看**分数差距**。融合通道 rank-1（分数 0.0328）与 rank-2（0.0161）
的 2 倍量级差，在 RRF 里被压缩成 1/(60+1) 与 1/(60+2) 的微小差；而交叉编码器把某候选
抬到 scored-rank-1 后，该候选拿到 1/(60+1) 的满额加成，足以反超。

## 决策
护栏改为**分数级归一化融合**，融合通道主导：

```
两路分数各自 min-max 归一化到 [0,1]，再按权重相加：
    final = w_fuse · fusedNorm + w_rerank · ceNorm
默认 w_fuse : w_rerank = 4 : 1（融合通道主导）。
```

- 融合通道的「最高分者」其 `fusedNorm = 1.0`，在 `w_fuse ≥ w_rerank` 时任何候选都追不上它，
  因此**强词法/语义命中不会被交叉编码器的个别错误打分挤出前列**；
- 交叉编码器只能在融合排序的近邻区间内做精细化重排（权重仅 1/4），无法整体推翻检索结论；
- 机械不变量（SPEC S17）：**重排后 top1 命中数不得差于重排前**，用对抗性打分器
  （故意把垃圾顶到第一）验证护栏真的兜底；selfcheck 单测覆盖。

## 后果
- +：从机制上杜绝「强命中被重排挤出」的退化，e2e 的精确关键词检索稳定可复现；
- +：融合信号主导，重排器即便整体偏弱也不会伤害检索质量；
- −：重排对排序的改动幅度被限制在融合近邻区间，极限增益低于裸重排；
- 需要裸排序的场景显式走 `rerankPlain()` 并自担风险；
- 已知代价：交叉编码器对每个候选各跑一次前向（depth=32 时单次检索约 3.6s），
  在 404 条黄金集上的全量评估耗时较长，属于性能优化项而非正确性缺陷。
